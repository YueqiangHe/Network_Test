# 江浙沪皖网络连通性测试与自动化指南

自动测试东京、新加坡、洛杉矶三个候选地址，每个目标默认发送 30 次 IPv4 ping，统计收到数量、丢包率、最小/平均/最大延迟，保存 CSV、JSON 和原始日志。三个目标并行测试，通常一两分钟完成，异常网络可能更久。

这是购买服务器前的 ICMP 初筛，**不验证代理连接、带宽或十人并发**。全部超时不等于一定被封锁，ping通也不保证代理可用。适用于约10名测试者，覆盖江苏、浙江、上海、安徽；候选地址、人员安排及手动测试步骤均在本文中。

## 准备

需要 Python 3.9 或更高版本，不需要安装 Python 第三方包。Windows、macOS 如未安装 Python，可从 https://www.python.org/downloads/ 获取适合系统的版本。

将本目录文件保存到电脑，在该目录打开终端。关闭已有代理、VPN和加速器（包括TUN），暂停下载、云盘同步和系统更新，并确认普通国内网页可以正常打开。使用今后实际连接代理的网络；Wi-Fi信号应稳定，有线与Wi-Fi分别记录。无需管理员权限；脚本不会更改网络设置，也不需要关闭防火墙或安全软件。

Ubuntu/Debian 如果缺少运行环境：

```bash
sudo apt update
sudo apt install python3 iputils-ping iproute2
```

## 一条命令开始

Windows，在 PowerShell 执行：

```powershell
py -3 network_test.py --win
```

如果没有 `py`，但 `python --version` 显示已安装 Python 3.9+，可使用 `python network_test.py --win`。

macOS：

```bash
python3 network_test.py --mac
```

Linux：

```bash
python3 network_test.py --linux
```

系统参数也可省略以自动选择；指定错误的系统会报错退出。这里的参数选择本机命令，不模拟其他系统。

## 记录编号、省市与运营商

每人使用独立编号；省市和实际接入运营商建议手动填写。以下命令还会尝试自动查询公网出口运营商：

Windows：

```powershell
py -3 network_test.py --win --tester T01 --region "江苏南京" --isp "电信" --detect-isp
```

macOS：

```bash
python3 network_test.py --mac --tester T02 --region "浙江杭州" --isp "联通" --detect-isp
```

Linux：

```bash
python3 network_test.py --linux --tester T03 --region "上海" --isp "移动" --detect-isp
```

测试手机热点时，可追加 `--connection hotspot`；Wi-Fi、有线可分别填 `--connection wifi`、`--connection ethernet`。手动值和自动检测值分别保存，不相互覆盖。

### 自动识别能做什么

- **Wi-Fi/有线**：默认读取系统的默认 IPv4 接口及网卡信息，尽力判断，不保证每个系统环境都成功。缺少系统工具、VPN、虚拟网卡、多出口环境可能导致 `unknown` 或选择不符合预期的接口。此元数据不等于对每个目标实际路由的逐一验证。
- **手机热点**：通常在电脑上表现为 Wi-Fi，无法据此可靠判断是否使用手机流量，需要手动标记。
- **运营商**：只有传入 `--detect-isp` 才通过 HTTPS 请求 `https://ipwho.is/`，使用服务返回的 ISP、组织和 ASN。该服务会看到请求来源公网 IP；本脚本不将测试者公网 IP 或精确位置写入结果。服务失败时记录失败，仍继续 ping。
- **识别准确性**：自动结果是公网出口组织，可能显示母公司、企业网关或VPN出口；不能保证准确识别电信/联通/移动，也不能用它确认测试者所在省市。实际接入运营商以手动值为参考。
- **Wi-Fi隐私**：不采集SSID、Wi-Fi密码、MAC地址、精确住址。接口名称可能由系统或用户自定义，分享前可以查看报告。

公网出口查询与ping流量可能走不同路径。请先关闭代理，再运行测试。本工具默认不调用公网IP查询服务。

## 查看与提交结果

每次运行创建独立时间戳目录，路径例如：

```text
results/
  20261111T120000000000Z/
    summary.csv
    report.json
    JP.log
    SG.log
    US.log
```

- `summary.csv`：每个目标一行，可以用 Excel 打开；包含测试编号、网络信息、时间、实际目标IP与统计。
- `report.json`：完整元数据和结果，包含查询状态、接口信息与系统版本。
- `*.log`：每次ping命令的原始输出，便于分析解析异常。

将本次时间戳目录完整打包给负责人。脚本记录 UTC 和本地时间（含时区）；请按北京时间白天、20～23点各跑一次，建议连续3天。切换宽带或热点后重新运行。

### 负责人合并10人的结果

把大家的结果按人分文件夹放入 `collected`，保留各自的 `summary.csv`：

```text
collected/
  T01/时间戳目录/summary.csv
  T02/时间戳目录/summary.csv
```

Windows：

```powershell
py -3 merge_results.py collected --out all_results.csv
```

macOS / Linux：

```bash
python3 merge_results.py collected --out all_results.csv
```

合并保留每条记录和来源文件，不把不同运营商、不同时间和不同目标IP混成一个平均值。不要重复放入同一份结果，以免重复计数。

## 统计含义与故障

- macOS的ping无回复时退出码为2，Linux通常为1；脚本分别处理。旧版脚本可能把macOS无回复误报为`command_error`和`0/0`，请使用更新后的`network_test.py`重新测试。
- 遇到`command_error`时查看终端错误详情和对应`*.log`，不能据此直接判定服务器被阻断。例如自定义目标的原始日志为`results/本次时间戳/T1.log`。
- `completed`：完整执行了采样，收到至少一个echo回复，不是代理测试通过。
- `no_echo_reply`：执行了采样，但没有收到echo回复。
- `dns_error`：域名解析失败；丢包率为空，不记为100%丢包。
- `command_error`：命令、权限或运行超时异常；已进行的统计只代表部分采样，需查看日志并重测。
- `attempted` 是实际完成的ping调用数，不保证操作系统将每个请求都成功发上网络。
- 延迟只对成功解析到延迟数值的echo回复计算；`latency_samples`为其数量。收到回复但延迟为空时，保留日志给负责人检查。
- Windows常见的“<1ms”按1ms上界参与计算，`latency_upper_bound_samples`记录此类数量，因此结果可能略偏高。
- 当前回复识别支持常见英文、简体中文和繁体中文ping输出。其他系统语言或编码需核对原始日志；Linux/macOS会尝试使用英文输出。
- 第一次运行可以先做本机自检。沙箱/容器禁止ICMP时，需在正常主机终端运行；无需为测试关闭防火墙。
- 按 `Ctrl+C` 会中断本轮，未保证生成完整汇总；重新运行即可。

## 手动测试（脚本无法运行时备用）

优先使用前面的自动脚本；下面的命令和提交模板仅供手动补测。

每次执行完一条命令，再执行下一条。每个目标通常需要几十秒；遇到大量超时可能更久，请等待最终统计。需要中止时按 `Ctrl+C`，并记录为“中止”，不要与完整 30 次测试直接比较。

### Windows 手动命令

打开“开始”菜单，搜索并打开 **PowerShell**，逐条粘贴：

```powershell
ping -4 -n 30 hnd-jp-ping.vultr.com
ping -4 -n 30 sgp-ping.vultr.com
ping -4 -n 30 lax-ca-us-ping.vultr.com
```

保存每条命令的开头和最后统计，包含目标 IPv4、发送/接收数量、丢包率、最小/最大/平均延迟。

### Linux 手动命令

打开终端，逐条执行：

```bash
ping -4 -c 30 hnd-jp-ping.vultr.com
ping -4 -c 30 sgp-ping.vultr.com
ping -4 -c 30 lax-ca-us-ping.vultr.com
```

保存目标 IPv4、`packets transmitted`、`received`、`packet loss` 和 `min/avg/max` 统计。如提示没有 `ping` 命令，记录系统发行版并联系测试负责人处理。

### macOS 手动命令

打开“终端”，逐条执行。macOS 的 `ping` 命令用于 IPv4：

```bash
ping -c 30 hnd-jp-ping.vultr.com
ping -c 30 sgp-ping.vultr.com
ping -c 30 lax-ca-us-ping.vultr.com
```

保存目标 IPv4、发送/接收数量、丢包率和 `min/avg/max` 统计。

### 域名无法解析时

如果出现“找不到主机”“Name or service not known”或“Unknown host”，记录为 **DNS 解析失败**，不要填写为“100% 丢包”。

负责人可从对应官方页面核实测试 IPv4 后，分发同一个地址让大家补测。把命令里的域名换成该 IPv4 即可，并在记录中注明“直接测试 IP”。

如果官方页面也无法打开，记录页面访问失败；页面失败与 ping 失败是不同的测试结果。

## 如何解读与选择候选机房

| 现象 | 本轮可以得出的结论 | 下一步 |
|---|---|---|
| 多次测试低丢包、延迟稳定 | 这个测试 IP 在这些网络和时段的 ICMP 表现较好 | 列入实际服务器试用候选 |
| 白天正常、晚间明显恶化 | 该路径可能有高峰拥塞，需进一步验证 | 优先比较其他候选并补测 |
| 所有请求超时 | 没有收到 ICMP 回复，原因尚不确定 | 核对地址、官方入口及其他连接测试 |
| 域名无法解析 | 尚未完成目标 IP 的 ping 测试 | 核实 IPv4 后补测 |
| 同一目标仅部分运营商表现差 | 网络表现存在差异 | 按运营商分别选线路，勿只看总平均 |
| 测试过程中本地断网 | 数据受本地故障影响 | 标记异常并重测 |

不按单次最低延迟决定购买。优先观察晚高峰、多次重复结果，以及是否有特定省份或运营商持续异常。

本指南不设“通过 ping 即可上线”的验收标准。30 个请求只适合快速初筛；即使显示零丢包，也不等于长期零丢包。

## 初筛后的下一阶段

1. 选出一到两个候选机房，确认短期计费、更换 IP、退款及流量计费规则。
2. 短期租用一台服务器，测试实际分配的公网 IPv4 与 SSH 连接。
3. 部署代理，为测试者生成独立配置。
4. 在 Windows、Linux、macOS 上验证导入配置、系统代理、TUN 权限及实际应用访问。
5. 先逐人连接排错，再安排 10 人同时连接，观察断线、实际速度、服务器负载和流量消耗。
6. 根据实测结果决定是否保留服务器及增加备用节点。

“10 个人分别 ping”不属于“10 人代理并发测试”；两者需要分阶段执行。最终只对实测覆盖的网络和系统记录为“验证可用”，保留测试日期。
